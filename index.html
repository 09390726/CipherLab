Caesar cipher pp. 283–284

A Caesar cipher is a substitution cipher: every letter moves the same number of places along the alphabet. That number is the key. After Z, the count loops back to A.

    Polyalphabetic cipher pp. 284–285

    A polyalphabetic cipher uses several shifts instead of one. The key is a sequence, such as 3-1-4: shift the first letter 3, the second 1, the third 4, then start the sequence again. "Poly" means many, so it uses many alphabets.

    Cipher text

    Look closelyWith key 314, the two Ls in POLYALPHABETIC both become P, but the two As become B and E. The same letter no longer always turns into the same cipher letter. That is what makes this harder to break than a Caesar cipher. The default example matches the case study on page 285.

    Vigenère cipher p. 285

    The Vigenère cipher is a polyalphabetic cipher whose key is a word. Each key letter gives a shift equal to its position in the alphabet, counting A as 0, so P = 15, I = 8 and E = 4. The keyword repeats under the whole message.

    The big problem: sharing the key

    Bob only gets the message if he has exactly the same key. Change one letter of Bob's key above and see what happens. So how does Alice get the key to Bob? If she sends it across the internet, Eve sees that too.

    Real symmetric encryptionHere the algorithm is Vigenère so you can follow every step. Real systems use AES. It mixes the data with a 128, 192 or 256-bit key through 10, 12 or 14 rounds of substituting bytes, shifting rows, mixing columns and adding the key. Your key above has . A 128-bit AES key has 2128, about 340 undecillion (3.4 × 1038). AES is fast and strong, but it still has the key-sharing problem. Asymmetric encryption solves that.

    Asymmetric encryption with RSA p. 287

    Asymmetric encryption uses two related keys. Bob's public key can be given to anyone, and it can only lock. His private key never leaves his device, and it is the only key that can unlock. Alice never needs a secret from Bob, so there is nothing for Eve to steal on the way.

    This is a working model of RSA with tiny numbers so you can see the maths. Each letter is turned into a number first: A = 10, B = 11 … Z = 35. Starting at 10 stops any letter from being 0 or 1, which RSA cannot hide.

    Can Eve work out the private key?

    Eve knows n. If she can find the two primes that multiply to make n, she can rebuild Bob's private key. With numbers this small, a computer does it instantly.

    Why real RSA is safeReal RSA keys use an n that is 2048 bits long: a number with about 617 digits. There is no known shortcut for finding its two primes, and trying them would take ordinary computers far longer than the age of the universe. This toy version has two other weaknesses that real RSA removes: the same letter always gives the same number, so frequency analysis works on it, and there are only a handful of possible keys.

    Digital signatures: running it backwards

    RSA can also prove who sent a message. Bob signs with his private key, and anyone can verify with his public key. If the message is changed on the way, the check fails. ECDSA does the same job using elliptic curves, which give the same security with much smaller keys.

    Symmetric and asymmetric compared

    SymmetricAsymmetric
    KeysOne secret (private) key, shared by sender and receiverA key pair: a public key to encrypt and a private key to decrypt
    Sharing the keyThe key has to reach the receiver without anyone else seeing itThe public key can be sent openly. The private key never leaves its owner
    SpeedFast, so it suits large amounts of dataMuch slower, so it suits small pieces of data such as keys and signatures
    Methods in this courseAES; also Caesar, polyalphabetic and VigenèreRSA, ECDH (agreeing a shared key), ECDSA (signatures)

    In real life, both work togetherWhen you open a secure (https) website, your browser and the server first use asymmetric maths such as ECDH to agree on a fresh secret key, with nothing secret sent across the internet. They then switch to fast symmetric AES, using that key, for the rest of the visit.
